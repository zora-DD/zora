## 文档维护原则

1. README 面向第一次接触项目的人，描述能力、配置和运行方式。
2. 项目亮点文档解释每项关键设计的业务问题、实现位置和选型理由。
3. 项目分析文档负责业务/数据/架构全貌和面试表达，不重复全部接口细节。
4. 项目技术文档解释代码如何工作、接口如何使用、如何扩展。
5. 面试问题总结只追加实际提出过的问题，不为了覆盖知识点预制问题。
6. 未完成能力必须明确标记，不能与已实现能力混写。
7. 代码修改涉及接口、事件、数据表或配置时，同一个变更中更新对应文档。
